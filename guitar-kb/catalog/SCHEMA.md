# Content Catalog Schema (v1)

The catalog is the app's content database, stored as JSON files in `catalog/`. It's generated by `build_catalog.py`, which also **checks the music data**: every chord voicing is checked note-by-note against its chord formula (including bass note), every movable shape is checked at frets 1–12, every scale position against its scale formula, and the triads and octaves are checked too. Every lesson's prerequisites and asset references are checked to exist, and the prerequisites are checked for cycles.

## Conventions
- Per-string arrays have 6 values, ordered **string 6 → string 1** (low E first). `-1` = muted, `0` = open.
- Standard tuning MIDI: 40 45 50 55 59 64. A fretted note's MIDI value = open string + fret.
- IDs are stable strings and are never reused. Lessons reference assets by ID.
- Scale position numbers follow the minor-pentatonic box numbering. The G major pentatonic "pos2" is the classic major box rooted at string 6, fret 3.

## Files
| File | Contents |
|---|---|
| `meta.json` | Schema version, string order, tuning |
| `tracks.json` | `{id, name, instrument: acoustic\|electric\|both, order, requires[]}` |
| `lessons.json` | `{id, track, title, prereqs[], pass_criteria, assets{}, content, review_days[]}` |
| `chords.json` | `{id, name, root, quality, bass?, frets[6], fingers[6], barre?{fret,from,to}, tags[], alt_of?}` |
| `shapes.json` | `movable_chords[] {id, quality, root_string, offsets[6] (null=muted)}`, `triads[] {id, root, quality, strings[], frets[]}`, `octaves[] {low_string, high_string, fret_offset}` |
| `scales.json` | `{id, name, root, kind, position, frets[6][], movable}` |
| `rhythm.json` | `strumming[] {id, meter, grid, steps[] (D/U/-/X), accents[] (step idx), swing, palm_mute?}`, `picking[] {id, meter, grid, steps[] {p\|i\|m\|a: string or 'root'/'alt_bass'}}` |
| `exercises.json` | `type: tab` → `{tempo?{start,target,step}, events[] {beat, string, fret, dur, tech?, bend?}, chords?[], fx?{}}`. Events on the same beat sound together (octaves, double stops). `tech: harmonic` sounds above the open string (fret 12 = +12, 7 = +19, 5 = +24); `tech: bend` + `bend` (semitones) is bent up from the fret to fret + bend; `tech: swell` is a volume swell (no pick attack). No `tempo` = played at your own pace · `type: chord_changes` → `{pairs[][], duration_s, target_per_min, voicings}` · `type: chord_progression` (M8, `chord_accuracy`) → `{meter, pace: timed\|own, bpm? (fixed click) \| tempo? (ladder, lesson has bpm), beats_per_chord? (timed), strums_per_chord? (own pace), pick: only\|random\|choose (which variant: the one, a key named at random, or you choose), show: chords\|numbers, variants[] {key, capo, chords[] (one per bar/box), numbers?[], shapes?, label, names? (chord names spelled for the key)}, decoys?[] (chords the lesson warns against, e.g. Fmaj7 for F), focus?[] (only these chords are graded, each must reach the ratio on its own), voicings}`. **Chord refs** in pairs/variants are a chord id, a triad id or `shape@fret` (`A_shape_minor@7`); `G\|G_4f` = either fingering counts. `voicings` is generated: `{ref: {name, frets[][] (each accepted fingering, without capo), where, root, quality, label? ('Bm (partial)')}}`, so graders build templates from the exact voicing (sounding pitch = fret + capo) |
| `songs.json` | `{id, title, words, tune, public_domain, meter, key, tempo, pickup_beats, capo_options[], sections[] {name, bars[], numbers[], lyrics[]}, chords_used[], rhythm[]}` |
| `quizzes.json` | `{id, lesson, type: generated\|ear, prompt (template), params{}}`. The app generates the questions |
| `song_outlines.json` | Modern worship songs stored as **facts only**: `{id, title, artist, ccli, original_key, bpm, meter, chart_key, sections[] {name, chords_in_chart_key[], numbers[]}, capo_options[] {shapes, capo}, practice_for[] (lesson ids), links{songselect}, sources{meta, chords}, chords_verified, notes}`. No lyrics, melody, or signature riffs. Generated by `build_song_outlines.py`, which converts every chord to Nashville numbers and flags anything outside the key |
| `setlist.json` | Your church's set list (from `HOPE_Worship_Songs.csv`): `{source, weeks, note, songs[] {name, plays, new, weeks_played[], last_played, outline_id, status: outline\|skipped\|public_domain_candidate\|pending_research, question}}`. The app can use it to build "songs we're playing this month" practice and to prioritize lessons. Generated by `build_setlist.py` |
| `content/{lesson}.md` | Teaching text for all 48 lessons (in `guitar-kb/content/`): markdown plus one-per-line embed tokens such as `{{chord:G_4f}}`, `{{chords:G_4f,Cadd9}}`, `{{shape:E_shape_major@3}}`, `{{outline:MS_…}}` (format in `06-app-spec.md` §8). The web test suite checks every token ID |

## User chart import (personal use)
The app should import charts the user already has access to, such as their SongSelect account or their church's charts:
- **Formats:** ChordPro (`.cho`, `.chordpro`, `.pro`: `{title:}`, `{key:}`, `{tempo:}`, `{time:}`, `{start_of_chorus}`, and `[G]` inline chords) plus plain "chords over lyrics" text paste.
- **On import:** parse the sections and chords, convert them to numbers using the chart's `{key:}`, and match the result to a `song_outlines` entry by CCLI number or title so it inherits the lesson links.
- **Storage:** imported charts stay on the device only. They are never bundled or synced into the catalog.
- **Tools that then work on any imported song:** transpose, capo suggestions, Nashville view, click at the chart tempo, chord-change drills built from the song's own progressions, and strum-pattern overlay.

## pass_criteria types
| type | fields |
|---|---|
| `changes_per_min` | `target`, `pair?` (one of the lesson's `chord_changes` pairs; without it every pair runs, and all must pass) |
| `timing` | `bpm`, `subdivision` (4/6/8/16), `max_err_ms`, `bars` |
| `pitch` | `cents?` (hold each target within ±cents for 0.5 s: `scope: all_strings` = the six open strings, else the lesson's bend exercise) · `note_accuracy?` (ratio of the exercise's notes matched in order) · `bpm?` (played to a click; tempo-ladder target, the exercise tempo must be 65% → bpm) · `any_octave?` (a note counts in any octave; default exact octave) |
| `chord_accuracy` | `ratio`, `bpm?` (played to a click on a tempo ladder; otherwise the exercise's `bpm` or your own pace) |
| `quiz` | `score`, `max_s?` |
| `self_check` | (none; optional recording) |

## On-device data (IndexedDB) — user progress
The catalog is read-only. Everything the app learns about the player lives in IndexedDB in Chrome on the phone (Dexie; `navigator.storage.persist()` requested), keyed by catalog IDs. Rules for how these rows change are in `06-app-spec.md` §5. Times are epoch milliseconds; `day` is the local calendar date `YYYY-MM-DD`.

| Table | Columns | Notes |
|---|---|---|
| `profile` | `id=1, instruments (acoustic\|electric\|both), handedness, created_at, catalog_version` | Single row |
| `lesson_progress` | `lesson_id PK, state (locked\|available\|in_progress\|passed), first_pass_at?, first_pass_day?, passed_at?, review_index (0–5), next_review_day?, mastered (bool), updated_at` | `review_index` points into the lesson's `review_days[]`; 5 = mastered |
| `practice_session` | `id PK, started_at, ended_at?, day, routine (15\|30\|free), total_s, tuned_at?` | Groups attempts from one sitting. `tuned_at` is set the first time the tuner is used in the session; it drives the "Quick tune" prompt (`06-app-spec.md` §3b) |
| `attempt` | `id PK, session_id FK, lesson_id?, exercise_id?, song_id?, criterion_type, bpm?, grader_mode (auto\|assisted\|self), input_route, score (0–1), metrics_json, met_target (bool), at_target_tempo (bool), is_review (bool), recording_uri?, at` | `metrics_json` holds type-specific detail: `mean_err_ms`, `hit_ratio`, `cents_dev`, `changes`, `correct/total`, per-answer times |
| `tempo_state` | `key PK (exercise_id or lesson_id), current_bpm, target_bpm, clean_streak, sloppy_streak, best_bpm, updated_at` | Tempo ladder per exercise |
| `calibration` | `key PK (input_route\|posture), input_route, posture (folded\|unfolded), offset_ms, spread_ms, method (strum), measured_at` | Subtracted from timing grades. Click-bleed arrival is re-measured from each attempt's count-in, so no separate loopback row |
| `quiz_item_stats` | `quiz_id, item_key, seen, correct, last_seen_at` · PK `(quiz_id, item_key)` | e.g. `item_key = "s5f7"`. Weights generated questions toward misses |
| `imported_chart` | `id PK, title, artist?, ccli?, key, tempo?, time?, capo?, source_filename, raw_text, matched_outline_id?, imported_at` | Raw ChordPro kept locally only |
| ~~`chart_section`~~ | not stored | Sections, chords and numbers are re-parsed from `raw_text` when a chart is shown (`web/src/chordpro.ts`), so there's nothing to keep in sync. Minor-key charts are numbered from the relative major (Em = 6m) |
| `song_practice` | `song_ref PK (outline id or "chart:<id>"), preferred_key?, preferred_capo?, last_practiced_at?, times_practiced` | Per-song personal settings |

The Arcade adds `games.json` to the catalog and seven game tables (`game_run`, `game_best`, `xp_ledger`, `streak`, `service_day`, `badge`, `daily_challenge`). They're defined in `07-games.md` §7.
**Built in G1:** `games.json` (all 12 games, levels for the six G1 tap games; `build_catalog.py` checks lesson refs, keys, numbers and zones), `game_run` (auto id), `game_best` (PK `key` = `game|level|mode`, `ghost` = `[[second, score], …]`), `xp_ledger` (auto id), `service_day`. The streak is computed from `practice_day` (game rounds and "Played a service" add the day), so there's no `streak` row yet; `badge` and `daily_challenge` arrive with G3.
**G2:** `practice_day` rows carry `active_s` (practice seconds that day, from the activity clock); a day counts with ≥ 300 s, a `service_day`, or (rows from before G2, without `active_s`) any practice. Freezes are recomputed from these rows (`web/src/streak.ts`), still no `streak` row. `game_run.mode` / `game_best` keys use `tap|play`. Games added: Octave Jump, Box Runner, In the Pocket (levels in `games.json`).

**Catalog updates:** on startup, if `meta.schema_version` or the catalog checksum changed, add `lesson_progress` rows for new lessons and recompute `locked/available` from prereqs. Never delete history: rows for IDs that disappear are kept and hidden. Backup/restore exports and imports all tables as one JSON file.
